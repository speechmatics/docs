# Input

## Supported input audio formats
Sessions can be configured to use two types of audio input: `file` and `raw`.  
We recommend using the `raw` option, unless you have a specific reason to use the `file` option.

:::tip
For capturing raw audio in the browser, try our [`browser-audio-input` package](https://www.npmjs.com/package/@speechmatics/browser-audio-input).
:::

### `audio_format`

The format must be supplied in the `audio_format` field of the `StartRecognition` message. See the [API reference](/api-ref/realtime-transcription-websocket#startrecognition).

## Language hints

Language hints are optional and apply only to the [Melia 1](/speech-to-text/models#melia-1) model, which detects supported languages automatically. For the Enhanced and Standard models, set `language` to a [supported language](/speech-to-text/languages) instead.

Hints tell the model which languages to expect in the audio, biasing detection toward them. They are most useful for short utterances, audio with heavy accents, or conversations where two languages sound similar, where they make language labeling more reliable.

Provide hints in the `StartRecognition` message as a list of [supported languages](/speech-to-text/languages#transcription-languages) to guide detection without restricting it. This config hints that the audio contains English and Arabic:

```json
{
  "message": "StartRecognition",
  "audio_format": {
    "type": "raw",
    "encoding": "pcm_s16le",
    "sample_rate": 16000
  },
  "transcription_config": {
    "model": "melia-1",
    // Melia 1 requires "multi" rather than a single language code
    "language": "multi",
    // highlight-start
    "language_hints": ["en", "ar"]
    // highlight-end
  }
}
```

The model can still detect and label a language you did not hint, and it labels only the languages it actually hears. To render each detected language correctly, refer to the [`LanguageInfo` message](/speech-to-text/realtime/output#languageinfo-message).

## Sending audio

After receiving a `RecognitionStarted` message, you can start sending audio over the Websocket connection. Audio is sent as binary data, encoded in the format specified in the `StartRecognition` message. See [Protocol overview](/api-ref/realtime-transcription-websocket#protocol-overview) for complete details of the API protocol.
