# Limits – Realtime

## Concurrent session limits

Speechmatics has no fixed cap on how many Realtime sessions you run at once. Your usage can grow as large as your application needs.

The only limit is how fast you add sessions. On the Pro plan, you can add up to 200 sessions in any 5 minutes, and up to 100 of them in any 1 minute. This protects the service from sudden spikes, so capacity is ready as your traffic grows.

Closing sessions gives the room back: close 50 sessions and you can open 50 new ones right away.

| Plan       | Sessions added in any 5 minutes | Of which in any 1 minute |
| ---------- | ------------------------------- | ------------------------ |
| Free       | 10                              | 2                        |
| Pro        | 200                             | 100                      |
| Enterprise | Custom                          | Custom                   |

:::note
Need higher limits? Reach out to [Support](https://support.speechmatics.com).
:::

### How session growth is measured

Speechmatics checks two rolling windows: the last 1 minute and the last 5 minutes. Growth in each window is counted from the highest number of sessions you had just before it, so closing and reopening sessions never counts as growth. Returning to a level you held in the last 10 minutes does not count against the 5-minute limit. Each window has its own limit, shown in the table above.

### What happens if you exceed your limit

New sessions beyond the limit are rejected: the server sends an in-band error followed by a WebSocket close with code `4005` (`quota_exceeded`). See the [Realtime API Reference](/api-ref/realtime-transcription-websocket#error) for details. Sessions you already have keep running.

Retry after a short wait. Room frees up as earlier growth leaves the window, or when you close sessions. For example, on the Pro plan:

- You add 100 sessions at 12:00. More are rejected until about 12:01.
- You add 200 sessions by 12:01. More are rejected until about 12:05.

## Session duration limits

Realtime SaaS sessions will be automatically ended if any of the following criteria are met:
- Session duration reaches 48 hours
- No audio data (AddAudio messages) sent for 1 hour
- No audio or ping/pongs sent for 3 minutes.

When a session is automatically ended, the Realtime SaaS service will send an in-band error followed by a closing handshake with code `1008`. For more information, see the [Realtime API Reference](/api-ref/realtime-transcription-websocket#error).

### Guidance for users

Clients can disconnect a session before it is automatically terminated and immediately reconnect a new session. Note that new sessions will typically start in less than a second.
If seamless transition is required, the new session can be connected a few seconds before disconnecting the old session.

Since unpredictable network issues can cause WebSocket connections to be dropped, we recommend graceful handling of session termination for long-running sessions.

## Custom dictionary limits

If a session's custom dictionary (`additional_vocab`) contains more than 20,000 items, the Realtime SaaS service sends an in-band error message of type [`protocol_error`](/api-ref/realtime-transcription-websocket#error) and closes the WebSocket connection with code `1003`. See [Custom dictionary content limits](/speech-to-text/features/custom-dictionary#maximum-number-of-custom-dictionary-items) for details.

## Data retention limits

Speechmatics Realtime SaaS does not store audio files, transcripts, or configuration data.
