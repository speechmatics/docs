# Sensitive data recognition and redaction

Speechmatics can find sensitive data in a Batch transcript, such as names, dates of birth, health conditions, and credit card numbers. You can use two features together or on their own:

- **Recognition** labels each sensitive value in the JSON transcript with its entity class.
- **Redaction** replaces each sensitive value with a label, such as `[name_given]`, throughout the transcript.

Recognition and redaction are available for Batch transcription in Speechmatics SaaS. They are not available in Realtime or on-prem deployments.

## Redact sensitive data

To redact sensitive data, set `enable_redaction` to `true` and list the [entity classes](#entity-classes) to redact in `redaction_config.entity_classes`:

```json
{
  "type": "transcription",
  "transcription_config": {
    "language": "en",
    "enable_redaction": true,
    "redaction_config": {
      "entity_classes": ["pii", "pci", "health"]
    }
  }
}
```

For the utterance "Mark was born on the 17th of January 2002.", the redacted JSON transcript looks like this (timings omitted):

```json
{
  "results": [
    { "type": "word", "alternatives": [{ "content": "[name_given]", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "was", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "born", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "on", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "the", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "[dob]", "speaker": "S1" }] },
    { "type": "punctuation", "alternatives": [{ "content": ".", "speaker": "S1" }] }
  ]
}
```

Redaction removes the original values throughout the JSON transcript.

## Recognize sensitive data

To recognize sensitive data without redacting it, set `enable_entities` to `true` and `entities_config.detect_advanced_entities` to `true`:

```json
{
  "type": "transcription",
  "transcription_config": {
    "language": "en",
    "enable_entities": true,
    "entities_config": {
      "detect_advanced_entities": true
    }
  }
}
```

Each recognized value appears in the JSON transcript as a result with `type` set to `entity` and an `entity_class`:

```json
{
  "results": [
    {
      "type": "entity",
      "entity_class": "name_given",
      "alternatives": [{ "content": "Mark", "speaker": "S1" }]
    },
    { "type": "word", "alternatives": [{ "content": "was", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "born", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "on", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "the", "speaker": "S1" }] },
    {
      "type": "entity",
      "entity_class": "dob",
      "alternatives": [{ "content": "17th of January 2002", "speaker": "S1" }]
    },
    { "type": "punctuation", "alternatives": [{ "content": ".", "speaker": "S1" }] }
  ]
}
```

## Recognize and redact sensitive data

To label every recognized value and redact the selected classes, combine both configurations:

```json
{
  "type": "transcription",
  "transcription_config": {
    "language": "en",
    "enable_entities": true,
    "entities_config": {
      "detect_advanced_entities": true
    },
    "enable_redaction": true,
    "redaction_config": {
      "entity_classes": ["pii", "pci", "health"]
    }
  }
}
```

Redacted values keep their `entity` type and `entity_class`, with the content replaced by the label:

```json
{
  "results": [
    {
      "type": "entity",
      "entity_class": "name_given",
      "alternatives": [{ "content": "[name_given]", "speaker": "S1" }]
    },
    { "type": "word", "alternatives": [{ "content": "was", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "born", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "on", "speaker": "S1" }] },
    { "type": "word", "alternatives": [{ "content": "the", "speaker": "S1" }] },
    {
      "type": "entity",
      "entity_class": "dob",
      "alternatives": [{ "content": "[dob]", "speaker": "S1" }]
    },
    { "type": "punctuation", "alternatives": [{ "content": ".", "speaker": "S1" }] }
  ]
}
```

## Configuration rules for recognition and redaction

A job that breaks these rules is rejected with a `400` error:

- `entities_config` requires `enable_entities: true`.
- `enable_redaction: true` requires `redaction_config.entity_classes` with at least one value, and no duplicates.
- `redaction_config` is only allowed when `enable_redaction` is `true`.
- If both `enable_redaction` and `enable_entities` are `true`, `entities_config.detect_advanced_entities` must also be `true`.

For example, this configuration enables redaction with the default entity detection:

```json
{
  "type": "transcription",
  "transcription_config": {
    "language": "en",
    "enable_entities": true,
    "enable_redaction": true,
    "redaction_config": {
      "entity_classes": ["pii", "pci", "health"]
    }
  }
}
```

The job is rejected with this error:

```json
{
  "code": 400,
  "error": "Invalid config",
  "detail": "enable_redaction requires advanced entity detection. When redaction is enabled, enable_entities must be false, or entities_config.detect_advanced_entities must be set to true."
}
```

When recognition or redaction is enabled, the transcript has no `spoken_form` or `written_form`, and the [smart formatting entity classes](/speech-to-text/formatting#entity-classes) (`cardinal`, `decimal`, `fraction`, `ordinal`, `percentage`, `span`, `measurement`) are not returned.

## Entity classes

Each value in `redaction_config.entity_classes` is either a group or a specific entity class. You can mix groups and entity classes in one list. A general class such as `name` or `location` also covers its more specific classes, such as `name_given` or `location_city`.

### Entity class groups

| Group | Covers |
|---|---|
| `pii` | Personally identifiable information |
| `pci` | Payment card information |
| `health` | Protected health information |
| `gdpr` | Personal data under the EU General Data Protection Regulation |
| `gdpr_sensitive` | Special categories of personal data under GDPR |
| `hipaa_safe_harbor` | Identifiers under the HIPAA Safe Harbor method |
| `cpra` | Personal information under the California Privacy Rights Act |
| `quebec_privacy_act` | Personal information under Quebec's privacy law (Law 25) |
| `appi` | Personal information under Japan's Act on the Protection of Personal Information |
| `appi_sensitive` | Special care-required personal information under APPI |

## Supported languages for recognition and redaction

Recognition and redaction support all [transcription languages](/speech-to-text/languages#transcription-languages), except:

- Bashkir
- Basque
- Esperanto
- Galician
- Interlingua
- Irish
- Maltese
- Marathi
- Mongolian
- Urdu
- Uyghur
- Welsh

For Mandarin, recognition and redaction support Simplified characters only.
