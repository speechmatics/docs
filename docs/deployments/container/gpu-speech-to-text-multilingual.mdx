# GPU Speech to text container (Melia 1 and Oak 1)

Melia 1 and Oak 1 are multilingual, GPU-only models. Oak 1 is tuned for healthcare audio. Both models run on the same transcriber and inference server images. For an overview, see [Melia 1](/speech-to-text/models#melia-1) and [Oak 1](/speech-to-text/models#oak-1).

## Prerequisites

- [A license file or a license token](/deployments/container/licensing)
  - There is no specific license for the GPU Inference Container, it will run using an existing Speechmatics license for the Batch Container
- [Access to our Docker repository](/deployments/container/accessing-images)

## System requirements

The system must have:

- Nvidia GPU(s) with at least 16GB of GPU memory
- Nvidia drivers (see below for supported versions)
- CUDA [compute capability](https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html#compute-capabilities) of 7.5-12.1 inclusive,
  which corresponds to the Turing, Ampere, Lovelace, Hopper, Blackwell architectures. Cards with the Volta architecture or below are not able to run the models
- 24 GB RAM
- The [nvidia-container-toolkit](https://github.com/NVIDIA/nvidia-docker) installed
- Docker version > 19.03

:::tip
See [Performance and cost](/deployments/container/performance-and-cost) for more information on the performance and cost of the container.
:::

### Nvidia drivers

- The GPU Inference Container is based on CUDA 13.0.1, which requires NVIDIA Driver release 580 or later.

Driver installation can be validated by running `nvidia-smi`. This command should return the Nvidia driver version and show additional information about the GPU(s).

#### Cloud instances

The GPU node can be provisioned in the cloud.

## Running the image

Currently, each GPU Inference Container can only run on a single GPU.
If a system has more than one GPU, the device must be specified using `CUDA_VISIBLE_DEVICES`
or selecting the device using the `--gpus` argument. See [Nvidia/CUDA documentation for details](https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html#cuda-environment-variables).

Pull the inference server image as described in [Accessing images](/deployments/container/accessing-images#melia-1-and-oak-1-models), then run it:

<CodeBlock language="bash">
  {`docker run --rm -it \\
    -v $PWD/license.json:/license.json \\
    --gpus '"device=0"' \\
    -e CUDA_VISIBLE_DEVICES \\
    -p 8001:8001 \\
    speechmaticspublic.azurecr.io/sm-asr-inference-server:${smVariables.latestMultilingualContainerVersion}
`}
</CodeBlock>

The inference server runs in one of two modes: Batch (the default) or Realtime. A server supports only one mode at a time.

The transcriber offloads inference to the server, so it does not require a GPU. It uses a single image for both modes, rather than the separate `rt-` and `batch-` images of the [Standard and Enhanced GPU container](/deployments/container/gpu-speech-to-text#batch-and-realtime-inference). Set `SM_ASR_MODE` to `batch` or `rt` to select the mode.

### Selecting a model

Set `model` to `melia-1` or `oak-1` in the transcription config, and set `language` to `multi`:

```json
{
  "transcription_config": {
    "model": "oak-1",
    "language": "multi"
  }
}
```

### Batch inference

Run the transcriber with `SM_INFERENCE_ENDPOINT` set to the gRPC endpoint of the inference server and `SM_ASR_MODE` set to `batch`:

<CodeBlock language="bash">
  {`docker run --rm -it \\
  -e SM_INFERENCE_ENDPOINT=<server>:<port> \\
  -e SM_ASR_MODE=batch \\
  -v $PWD/license.json:/license.json \\
  -v $PWD/example.wav:/input.audio \\
  speechmaticspublic.azurecr.io/sm-asr-transcriber:${smVariables.latestMultilingualContainerVersion}
`}
</CodeBlock>

To accept multiple jobs over an HTTP API without restarting the container between jobs, run the transcriber as a [batch persistent worker](/deployments/container/batch-persistent-worker).

### Realtime inference

To run the inference server in Realtime mode, set `SM_STREAMING=true`:

<CodeBlock language="bash">
  {`docker run --rm -it \\
    -v $PWD/license.json:/license.json \\
    --gpus '"device=0"' \\
    -e CUDA_VISIBLE_DEVICES \\
    -e SM_STREAMING=true \\
    -p 8001:8001 \\
    speechmaticspublic.azurecr.io/sm-asr-inference-server:${smVariables.latestMultilingualContainerVersion}
`}
</CodeBlock>

When the server is ready, the model table lists the streaming models:


Run the transcriber with `SM_INFERENCE_ENDPOINT` set to the gRPC endpoint of the inference server and `SM_ASR_MODE` set to `rt`:

<CodeBlock language="bash">
  {`docker run --rm -it \\
  -e SM_INFERENCE_ENDPOINT=<server>:<port> \\
  -e SM_ASR_MODE=rt \\
  -v $PWD/license.json:/license.json \\
  -p 9000:9000 \\
  speechmaticspublic.azurecr.io/sm-asr-transcriber:${smVariables.latestMultilingualContainerVersion}
`}
</CodeBlock>

Connect over WebSocket as described in [Realtime transcription](/deployments/container/cpu-speech-to-text#realtime-transcription), and select the model in the `StartRecognition` message. For the Realtime features both models support, refer to [Melia 1 and Oak 1 on Realtime](/speech-to-text/models#melia-1-and-oak-1-on-realtime).

Realtime inference requires container version 1.13.0 or later.

#### Multi-session containers

By default, the Realtime transcriber accepts one WebSocket connection at a time. To accept more, set `SM_MAX_CONCURRENT_CONNECTIONS` to the maximum number of sessions. The `/ready` [health check endpoint](/deployments/container/cpu-speech-to-text#health-service) then returns true while a connection is free.

CPU usage scales with the number of active sessions. Most memory is shared between sessions.

### Monitoring the server

The inference server is based on [Nvidia's Triton architecture](https://developer.nvidia.com/nvidia-triton-inference-server) and as such
can be monitored using Triton's inbuilt Prometheus metrics, or the GRPC/HTTP APIs. To expose these, configure an external mapping for port
8002(Prometheus) or 8000(HTTP).
