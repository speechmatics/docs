# How on-device deployment works

:::info
On-device deployment is coming soon. Its feature coverage is currently narrower than SaaS on Cloud and on-prem deployments.
:::

On-device deployment runs Speechmatics speech-to-text inside your own application, on the end user's machine. Audio never leaves the device, and transcription needs no network connection.

## Components of an on-device deployment

An on-device deployment has three parts, all available from the [Portal](https://portal.speechmatics.com/):

| Component | What it is |
|---|---|
| Speechmatics on-device SDK | A shared library with a C API, plus prebuilt and source copies of the example apps. One archive per platform. |
| Language packs | The encrypted models for one language. One archive per language, shared by all platforms. |
| License | A token that unlocks the SDK. Your application supplies it before creating an engine. |

The SDK bundles everything it needs to run the models, including ONNX Runtime. Your application sends audio in and receives transcripts through callbacks.

## Supported platforms

The Speechmatics on-device SDK is available for the following platforms:

| Platform | Architectures | Minimum OS | Hardware acceleration |
|---|---|---|---|
| Linux | x86_64, ARM64 | glibc 2.35 (Ubuntu 22.04, Debian 12) | None (CPU only) |
| macOS | Apple silicon | macOS 13 Ventura | CoreML |
| Windows | x86_64, ARM64 | Windows 11 | DirectML |

Intel-based Macs are not supported. CUDA is not available.

## Processing modes

The SDK transcribes audio in one of two modes:

- **File mode:** the engine reads a whole audio file and returns one aggregate JSON transcript.
- **Streaming mode:** your application feeds audio as it arrives, and the engine returns partial and final transcripts as it goes. Use this for a microphone or network audio source.

Both modes take a JSON job config with the same [`transcription_config`](/api-ref/batch/create-a-new-job) object as the other Speechmatics deployments, but not every feature is supported on-device.
