# Set the on-device SDK license

The Speechmatics on-device SDK needs a license before it transcribes any audio. To get one, speak to [Support](https://support.speechmatics.com).

The SDK validates the license each time your application calls `sm_create_engine`, before it reads the language pack, and again periodically during transcription. Validation works offline. If the license is missing or invalid, [`sm_check_error`](/deployments/on-device/api-reference#sm_check_error) on the new engine returns `SMEngineError` with a `detail` that starts with `License check failed: `.

Each engine is licensed independently. For each engine, the SDK uses the first license token it finds, in this order:

1. The `license_token` field of the engine's `SMEngineConfigOverride`.
2. The token set with `sm_set_license_token()`.
3. The `LICENSE_TOKEN` or `SM_LICENSE_FILE` environment variable.

## Pass the license with sm_set_license_token

Embed the license in your application and pass it with `sm_set_license_token()`. This is the preferred method, because the license stays inside your application rather than being visible on the end user's machine.

The token is the `signedclaimstoken` value from the `license.json` Speechmatics gives you. Call `sm_set_license_token()` once, before creating any engine:

```cpp
#include <cstring>
#include <smapi/smapi_managed.h>

// Token compiled into your application, not read from disk
static const char kLicenseToken[] = "<signedclaimstoken>";

int main() {
  // Set the license once, before any sm_create_engine call
  sm_set_license_token(kLicenseToken, std::strlen(kLicenseToken));
  // ... create engines and transcribe ...
}
```

To make the token harder to extract from your binary, store it obfuscated and decode it just before the call.

`sm_set_license_token()` is not safe to call at the same time as `sm_create_engine`. Call it before your application starts any transcription threads. Engines created before the call keep the license they started with.

## Pass the license in the engine config

To license one engine without the process-wide setting, set the `license_token` and `license_token_len` fields of the `SMEngineConfigOverride` you pass to `sm_create_engine`. A token here takes precedence over `sm_set_license_token()` for that engine, so engines in one process can run under different licenses:

```cpp
SMEngineConfigOverride cfg = {};
// License this engine alone. sm_create_engine copies the token.
cfg.license_token = kLicenseToken;
cfg.license_token_len = std::strlen(kLicenseToken);

void *engine = sm_create_engine(langpack.c_str(), langpack.size(), &cfg,
                                nullptr, nullptr, nullptr, true, nullptr);
```

The token's memory doesn't need to outlive the call. Setting the field doesn't change the token set with `sm_set_license_token()`.

## Set the license with an environment variable

For evaluation and for running the example apps, the SDK can also read the license from the environment. It checks these variables only when neither the engine config nor `sm_set_license_token()` supplies a token:

| Variable | Value |
|---|---|
| `LICENSE_TOKEN` | The token itself: the `signedclaimstoken` value from `license.json`. |
| `SM_LICENSE_FILE` | The path to `license.json`. The SDK reads the token from it. |

Either variable exposes the license to anyone with access to the machine. Don't rely on them in an application you ship to end users.
