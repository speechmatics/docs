# Set the on-device SDK license

The Speechmatics on-device SDK needs a license before it transcribes any audio. To get one, speak to [Support](https://support.speechmatics.com).

You set the license once, for the whole SDK. It then applies to every engine your application creates, and it can't be changed until the process restarts. Validation works offline.

The SDK takes the license from the first of these to happen:

1. Your application calls `sm_set_license_token()`.
2. Your application calls `sm_create_engine` for the first time. The SDK then reads the `LICENSE_TOKEN` or `SM_LICENSE_FILE` environment variable.

Each `sm_create_engine` call checks the license again before it reads the language pack, and the SDK checks it periodically during transcription. If the license is missing, invalid or has expired, [`sm_check_error`](/deployments/on-device/api-reference#sm_check_error) on the new engine returns `SMEngineError` with a `detail` that starts with `License check failed: `.

## Pass the license with sm_set_license_token

Embed the license in your application and pass it with `sm_set_license_token()`. This is the preferred method, because the license stays inside your application rather than being visible on the end user's machine.

The token is the `signedclaimstoken` value from the `license.json` Speechmatics gives you. Call `sm_set_license_token()` once, before creating any engine, and check what it returns:

```cpp
#include <cstring>
#include <iostream>
#include <smapi/smapi_managed.h>

// Token compiled into your application, not read from disk
static const char kLicenseToken[] = "<signedclaimstoken>";

int main() {
  // Set the license once, before any sm_create_engine call
  if (sm_set_license_token(kLicenseToken, std::strlen(kLicenseToken)) != SMLicenseOk) {
    std::cerr << "license is not valid\n";
    return 1;
  }
  // ... create engines and transcribe ...
}
```

To make the token harder to extract from your binary, store it obfuscated and decode it just before the call.

`sm_set_license_token()` returns an [`SMLicenseStatus`](/deployments/on-device/api-reference#smlicensestatus):

- `SMLicenseOk`: the license is set and valid.
- `SMLicenseNotValid`: the license is set but isn't valid. No engine can be created until the process restarts. Engine creation reports why in `sm_check_error`.
- `SMLicenseAlreadySet`: the license was already set, by an earlier call or by the first `sm_create_engine`. Nothing changed.

You can call `sm_set_license_token()` from any thread, including while another thread calls `sm_create_engine`. Whichever comes first sets the license.

## Set the license with an environment variable

For evaluation and for running the example apps, the SDK can also read the license from the environment. If your application hasn't called `sm_set_license_token()`, the first `sm_create_engine` call reads one of these variables:

| Variable | Value |
|---|---|
| `LICENSE_TOKEN` | The token itself: the `signedclaimstoken` value from `license.json`. |
| `SM_LICENSE_FILE` | The path to `license.json`. The SDK reads the token from it. |

Either variable exposes the license to anyone with access to the machine. Don't rely on them in an application you ship to end users.
